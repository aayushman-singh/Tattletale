# Codex review — Phase 2 (correlation + signed custody)

_Findings only; model gpt-5.5 xhigh._

---

**Findings**

- **Blocker: the PDF claims the wrong root is signed.** `runReplay.ts` renders the PDF with `preChain.rootHash`, then signs `finalChain.rootHash`. But `pdf.ts` says the manifest carries an Ed25519 signature over “this root hash.” It does not. Since the final root includes the PDF bytes, it cannot be embedded in the PDF without circularity. Rename the PDF value as a pre-PDF artifact root or remove the signature claim from the PDF.

- **Blocker: the signing model is not attributable or tamper-resistant against a malicious rewrite.** `sealRootHash()` silently generates a fresh key and embeds the public key beside the signature. Anyone can modify artifacts, recompute the root, generate a new key, and produce a valid-looking manifest. This verifies internal consistency only, not custody attribution. A real seal needs an externally trusted public key/key id, and missing key material should fail unless explicitly running demo mode.

- **Blocker: the correlation score is not defensible as forensic confidence.** The weights and thresholds are hand-tuned constants with no calibration, validation set, likelihood model, or uncertainty. Calling cluster averages `confidence` overstates what the number means. It is a heuristic score, not a probability or forensic confidence.

- **Blocker: sparse/missing data can create false merges.** Two accounts with identical handle + display name + no posts get `styleSimilarity = 1` because empty style features all match, producing `0.24 + 0.12 + 0.22 = 0.58`, above the merge threshold. One-caption temporal/style signals also get full weight. Behavioural evidence must be coverage-gated or downweighted by sample size.

- **Blocker: union-find transitive clustering can over-merge identities.** If A-B and B-C barely cross threshold, A and C merge even if A-C is weak or contradictory. Identity resolution needs cluster-level consistency, not only pairwise chaining. Use complete-link/min-edge checks, negative evidence, or require all member pairs to satisfy a merge policy.

- **High: single-account “confidence: 1” is misleading.** A singleton has no corroborating identity evidence, but the graph/PDF reports confidence `1`. That reads as certainty. It should be `null`, `n/a`, or “not correlated.”

- **High: `deriveMatches()` can label the wrong username.** It finds `primaryHandle` globally, not within the current cluster. If there are multiple merged identities, every match can be reported under the target handle even when that handle is not part of that identity.

- **High: the method string lies.** It says “stylometric & hour-of-day cosine”; style is not cosine. `buildIdf()` is not IDF either, just document frequency filtering. “shared rare terms” is also weak: with two accounts, every shared term qualifies as “rare.”

- **Medium: determinism is input-order dependent.** Cluster ids, layout, platform order, edge tie ordering, and root hashes change if the same accounts arrive in a different array order. For forensic replay, canonicalize account ordering before scoring/layout.

- **Medium: malformed timestamps are silently ignored.** `hourHistogram()` drops invalid timestamps by checking `Number.isNaN(h)`. For this project’s failure posture, bad evidence should raise with context, not quietly weaken one feature.

- **Medium: UI legend conflates band with merge state.** Scores `0.55–0.619` are merged but rendered as amber `medium`, while the legend says amber means “flagged, not merged.” Color/dash should be driven by merge state first, score band second.

- **Test gaps:** add adversarial tests for empty posts, one-post accounts, chain merges, reordered input, unrelated same-name/similar-handle accounts, invalid timestamps, PDF root-vs-manifest seal mismatch, and verification against an expected public key instead of the embedded one.

REMAINING BLOCKERS: PDF signs/claims wrong root; self-signed ephemeral seal is not attributable; sparse-data scoring false-merges; union-find transitive over-merge; deriveMatches can mislabel clusters
